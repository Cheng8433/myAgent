# ADR 002 · 日报保持确定性，另起一个真正 Agent 化的匹配场景

- 状态：已采纳（2026-10-20，M10）
- 相关：`docs/PLAN.md` 原则一与 §M10、`src/workflows/daily_report.py`、
  `src/workflows/job_match.py`、`src/agent/tools/job_search.py`

## 背景

项目做完 M0–M9 后，生产主流程是确定性脚本：抓取 → 入库 → 渲染 → 落盘，
LLM 只在最后做一次无工具摘要。这个结构符合 PLAN 原则一（流程确定，LLM 只做判断题），
但也让"工具调用、多轮决策"这些 Agent 的核心从未在生产路径上发生 ——
项目看起来更像一个 Agent 脚手架加一条固定流水线。

问题不是"日报做得不够智能"，而是**缺少一个值得让模型自主决策的场景**。

## 选项

| 方案 | 优点 | 代价 |
|---|---|---|
| 把日报改成 ReAct | 表面上"更像 Agent" | 用自主性换确定性：抓取、去重、额度这些必须可控的步骤变得不可预测；成本与失败面都变大 |
| 只做文档说明"这也是 Agent" | 零改动 | 不解决"没有真实决策"的问题，面试时讲不实 |
| **另起岗位匹配场景（选中）** | 日报的确定性不动；匹配天然需要检索、比较、取舍；可做 A/B | 多一个工作流、三个工具和一套评估；需要标注语料 |

## 决定

- `daily_report` 保持确定性，不把生产主流程改成 ReAct。
- 新增 `workflows/job_match.py`：基于本地 `jobs` 库做检索 → 详情 → 排序 → 提交，
  提供 `workflow` / `single` / `agent` 三种模式，同一份档案、同一候选池、同一模型下对比。
- Agent 的成败以"有没有真的调用 `save_shortlist` 落盘"为准，`latest.json` 必须比本次
  run 更新；不拿上一次的清单冒充。
- 匹配**不写 `runs` 表**：避免误占 ncss 当日额度、污染日报成本看板。
- 外部岗位数据走 `untrusted=True` 隔离；`save_shortlist` 只信 id，标题与 URL 回库回填。

## 后果

**得到**

- 项目里第一次出现"模型自己决定下一步调什么工具"的生产级代码路径，且可离线回归。
- 三种做法可以放在一张表上比较质量、schema 合法率、token、调用次数与耗时。
- 日报的确定性与合规护栏没有被动摇。

**认下的账**

- 标注语料只有 12 条，A/B 是定性演示，不是统计实验。
- 真实库没有人工标注，只能报成本与合法率，不能报 precision。
- `get_job` 没有 JD 全文（`jobs` 表不存），匹配依据仍是结构化字段。
- 匹配是单用户 CLI 假设，`latest.json` 不做并发保护。

## 何时重新考虑

- 如果将来要让日报按"当天简历/档案"过滤推荐，可以把匹配作为日报之后的一步，
  但仍然不应把抓取与额度控制交给模型。

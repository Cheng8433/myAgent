# ADR 001 · 用 Windows 任务计划程序做无人值守

- 状态：已采纳（2026-10-20，M9）
- 相关：`docs/PLAN.md` §M9、`docs/DEPLOY.md`、`src/app/lock.py`、`src/app/heartbeat.py`

## 背景

每次运行 = 一天一次、大约几分钟的批处理，不是一个常驻服务。
需要的是：按时启动、同一时刻只有一份、退出码可读、失败可查、可一键停用。
本项目跑在主人自己的 Windows 11 桌面上，数据源是实名账号，频率必须受控。

## 选项

| 方案 | 优点 | 代价 |
|---|---|---|
| **Windows 任务计划程序**（选中） | 系统自带、无需常驻、MultipleInstances 直接防叠加、退出码进事件 | 用户未登录时不执行；配置在系统里，不在仓库里（已用脚本固化） |
| APScheduler 常驻进程 | 进程内细粒度控制、跨平台 | 常驻占资源；自己实现单实例、崩溃重启、开机自启——等于重写任务计划程序 |
| NSSM 注册为服务 | 开机自启、崩溃自动重启 | 多一个第三方工具；服务账户下拿不到桌面环境，Playwright 登录这类交互更难；本项目每天只跑一次，收益不抵复杂度 |

## 决定

任务计划程序 + 一个仓库内的包装脚本：

- 任务动作只有 `cmd.exe /c scripts\run_report.cmd`——工作目录、`PYTHONUTF8=1`、
  venv 路径、日志重定向全部收在脚本里，**手动跑与自动跑是同一个入口**。
- `MultipleInstances=IgnoreNew` 防任务叠加；`src/app/lock.py` 的 OS 级文件锁
  再兜住"人手动跑 + 任务同时跑"这条任务计划程序管不到的路径。
- 触发时间 08:00，`StartWhenAvailable` 让关机错过的任务在下次开机后补跑。
- 注册 / 卸载写成 `scripts/register_task.ps1` / `unregister_task.ps1`，
  系统状态可复现、可回滚，不靠"我记得当时点了哪里"。

## 后果

**得到**

- 部署形态简单：没有常驻进程要维护，出问题先跑 `run_report.cmd` 复现。
- 单实例有两层（调度器 + 文件锁），且锁没有僵尸状态。
- 退出码 0/1/2/3/4 可直接从任务计划程序读到，`task.log` 保留进程级输出。

**认下的账**

- 任务以当前用户身份运行，**用户未登录时不会执行**；要"未登录也跑"必须
  在系统里存账户密码，安全代价不值得为一个每日批处理付。
- 外部告警（飞书）暂缓：本机心跳能回答"最近跑没跑"，但人不在电脑前时
  它不会主动喊人。这是 `docs/DEPLOY.md` §5 写明的欠账。
- 任务计划程序的配置不在 git 里，只有生成它的脚本在；换机器要重跑一次注册脚本。

## 何时重新考虑

- 需要跨机器/跨平台部署 → 换容器或云函数（届时锁与心跳都要重新设计）。
- 需要"用户未登录也跑" → 评估 Windows 服务（NSSM）或计划任务存凭据的安全成本。
- 同一天需要多次运行、或要细粒度退避 → 再考虑常驻调度器。
